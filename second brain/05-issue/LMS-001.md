## User Story

As a new GRC user, I want to sign up and log in with email and password, so that I can access the platform without depending on a third-party identity provider.

## Acceptance Criteria

1. User can sign up with email + password and receive a session cookie
2. User can log in with the same credentials and receive a session cookie
3. User can log out and the session is revoked server-side
4. `GET /auth/me` returns the current user when authenticated, 401 otherwise
5. Wrong credentials return a generic 401 (no email-existence enumeration)
6. Sign-up and login are rate-limited (10/min/IP)
7. Passwords stored as bcrypt (cost 12); never logged
8. Audit log entry on signup, login (success + failure), logout

## Non-functional (not generic to all features)

- Session cookies: HttpOnly, Secure, SameSite=Lax
- Constant-time credential comparison
- 30-day rolling session expiry
- Reject common-password list at sign-up

## Out of Scope (this issue)

- OAuth providers (Google / Apple / LinkedIn) — deferred to 1.0.1
- Password reset, email verification, MFA — separate epic
